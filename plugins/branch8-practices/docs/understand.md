# Stage 1: Confirm the task

Record status: `understanding`.

The RD usually picks the ticket before reading it. This stage only makes sure
you both have the same picture of what the ticket says. Judging it - gaps,
conflicts, risks - is stage 2's job, so do not start that here.

1. **Give a neutral digest, without interpretation.** Gather the ticket
   description, attachments and any linked PRD. Organise what they say - keep
   their section order and wording, quote key sentences, list the stated
   purpose, scenarios, rules, constraints and acceptance criteria - but do not
   add what you think it is for or why. For long material, digest each part
   briefly and say which parts are long. End with the Jira link and a nudge to
   read the full ticket there.
   - A link or attachment you cannot open (no connector, no access): say which
     one and ask for it to be pasted or connected. Never summarise or guess
     content you have not read. If you could read only part of something (a
     long result cut to a preview), say which part.
2. **Confirm with a question card**: "The digest is right - continue" /
   "Other": the RD adds, corrects, or flags anything that feels off. Do not
   ask them to restate the ticket in prose.
3. Write the confirmed digest into the record's Purpose section, with the RD's
   corrections and additions. Anything they flagged is carried into stage 2
   as an issue to check. Set status `reviewing` and read `review.md` next to
   this file.
